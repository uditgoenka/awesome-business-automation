# Contribution Guidelines

Thank you for your interest in contributing to **Awesome Business Automation**! Please ensure your pull request adheres to the following guidelines.

## Adding a New Entry

### Requirements

- **Real tools only.** Every entry must link to an active, publicly accessible repository or product.
- **Business relevance.** The tool must solve a real business automation problem — not purely developer tooling or academic research.
- **Verified URLs.** Double-check that GitHub links follow the `github.com/owner/repo` format and resolve correctly.
- **Quality threshold.** Open-source repos should have meaningful adoption (stars, forks, recent commits). Proprietary tools should have documented APIs or integrations.

### Format

Use the following entry format with an em dash (not a hyphen):

```markdown
- [owner/repo](https://github.com/owner/repo) — Short description of what the tool does and why it matters for business automation.
```

- Start descriptions with a capital letter.
- End descriptions with a full stop.
- Use Australian English (organisation, colour, favour, etc.).
- Keep descriptions to one or two sentences.
- Place new entries at the end of the relevant section.

### Categories

If your tool does not fit any existing category, propose a new section in your PR description with a rationale for why it deserves its own category.

## Pull Request Process

1. **Fork** the repository and create a new branch for your addition.
2. **Add your entry** following the format above.
3. **One tool per PR** — keep pull requests focused and easy to review.
4. **Fill out the PR template** completely.
5. **Check your links** — broken URLs will not be merged.

## Updating an Existing Entry

If a project has moved, been renamed, or its description is outdated:

1. Update the URL and/or description.
2. Explain the change in your PR description.

## Removing an Entry

If a project has been archived, abandoned, or is no longer relevant:

1. Remove the entry.
2. Provide evidence in the PR description (e.g., archived repo, no commits in 2+ years).

## Code of Conduct

By contributing, you agree to be respectful and constructive. Spam, self-promotion without genuine value, and low-effort submissions will be closed without review.

## Questions?

Open an issue if you are unsure whether a tool fits the list. We are happy to discuss before you invest time in a PR.
